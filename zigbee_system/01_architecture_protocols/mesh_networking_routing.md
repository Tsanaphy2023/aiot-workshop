# 🕸️ ระบบเครือข่ายร่างแหและการหาเส้นทาง (Mesh Networking & Routing Mechanisms)

---

## 1. บทบาทของอุปกรณ์ในระบบ Zigbee (Device Logical Roles)

ในเครือข่าย Zigbee 3.0 อุปกรณ์จะถูกแบ่งบทบาทหน้าที่ออกเป็น 3 ประเภทหลักตามฟังก์ชันและการใช้พลังงาน:

```
        ┌─────────────────────────┐
        │  Zigbee Coordinator (ZC)│ (ต่อไฟตรง, คุม Gateway, มี 1 ตัวต่อ PAN)
        └────────────┬────────────┘
                     │ (ไร้สาย)
          ┌──────────┴──────────┐
          │                     │
┌─────────▼────────┐   ┌────────▼─────────┐
│ Zigbee Router    │   │ Zigbee Router    │ (ต่อไฟตรง, ช่วยกระจายสัญญาณ Mesh)
│      (ZR-1)      │   │      (ZR-2)      │
└─────────┬────────┘   └────────┬─────────┘
          │                     │
     ┌────┴────┐           ┌────┴────┐
     ▼         ▼           ▼         ▼
  ┌─────┐   ┌─────┐     ┌─────┐   ┌─────┐
  │ ZED │   │ ZED │     │ ZED │   │ ZED │  (ใช้ถ่าน/แบตเตอรี่, หลับ Deep Sleep)
  │ ดิน │   │อากาศ│     │ แสง │   │ วาล์ว│
  └─────┘   └─────┘     └─────┘   └─────┘
```

### 1.1 Zigbee Coordinator (ZC) - ผู้ประสานงานเครือข่าย
* **จำนวนในระบบ:** มีได้เพียง **1 ตัวเท่านั้น** ต่อ 1 Personal Area Network (PAN)
* **หน้าที่หลัก:**
  1. ก่อตั้งเครือข่าย (Initialize Network) โดยการสแกนหาความถี่ 2.4 GHz ที่มีสัญญาณรบกวนน้อยที่สุด และเลือก Channel (เช่น Channel 25)
  2. กำหนดรหัส **PAN ID** (ทั้ง 16-bit PAN ID และ 64-bit Extended PAN ID)
  3. แจกจ่าย Network Key และบริหารจัดการการอนุญาตให้อุปกรณ์ใหม่เข้าร่วมเครือข่าย (Permit Join)
  4. ทำหน้าที่เป็นศูนย์กลางสะพานเชื่อมต่อ (Gateway Bridge) ส่งข้อมูลต่อไปยังระบบคอมพิวเตอร์/คลาวด์ ผ่านโปรโตคอล MQTT หรือ REST API
* **การใช้พลังงาน:** ต้องต่อไฟตรงตลอดเวลา (Mains Powered / Constant Power)

### 1.2 Zigbee Router (ZR) - โหนดกระจายสัญญาณและหาเส้นทาง
* **ฮาร์ดแวร์:** เป็นอุปกรณ์ประเภท Full Function Device (FFD)
* **หน้าที่หลัก:**
  1. เชื่อมต่อกับ ZC หรือ ZR ตัวอื่นเพื่อสร้างโครงร่างแห (Mesh Topology)
  2. ส่งต่อแพ็กเกตข้อมูล (Forward Data Packets) ระหว่างโหนดที่อยู่ห่างไกล (Multi-Hop)
  3. รับบทบาทเป็น **Parent Node** คอยเก็บกล่องข้อความ (Mailbox Buffer) ให้กับลูกข่ายที่เป็นอุปกรณ์หลับ (ZED)
* **ตัวอย่างอุปกรณ์ในแปลงเกษตร:** ปลั๊กไฟอัจฉริยะในโรงเรือน, โหนดควบคุมปั๊มน้ำที่ต่อไฟบ้าน, เสากระจายสัญญาณ Repeater กลางแจ้งแบบมีแผงโซลาร์เซลล์ขนาดใหญ่
* **การใช้พลังงาน:** ภาครับวิทยุเปิดตลอดเวลา จึงต้องต่อไฟตรงหรือใช้ระบบโซลาร์เซลล์ที่ไม่ตัดไฟ

### 1.3 Zigbee End Device (ZED) - โหนดปลายทาง (เซนเซอร์)
* **ฮาร์ดแวร์:** เป็นอุปกรณ์ประเภท Reduced Function Device (RFD)
* **หน้าที่หลัก:**
  1. วัดค่าจากเซนเซอร์ (เช่น อุณหภูมิ, ความชื้นดิน, แสง)
  2. ส่งข้อมูลขึ้นไปยัง Parent Node (ZR หรือ ZC)
  3. ไม่ทำหน้าที่ส่งต่อข้อมูลให้คนอื่น (No Routing capability) ทำให้ใช้หน่วยความจำน้อยมาก
* **จุดเด่น:** **สามารถเข้าสู่โหมดหลับลึก (Deep Sleep) ได้** เมื่อไม่ส่งข้อมูล โดยจะกินกระแสไฟเฉลี่ยเพียง **10 – 20 µA** ทำให้ทำงานด้วยถ่านกระดุม CR2450 หรือถ่าน 18650 ได้นาน 1 – 3 ปี

## 2. ขั้นตอนวิธีและกลไกการส่งข้อมูล (Routing Mechanisms)

### 2.1 AODV (Ad-hoc On-Demand Distance Vector Routing)
Zigbee ไม่จำเป็นต้องเก็บแผนผังเส้นทางของทุกจุดตลอดเวลา แต่จะค้นหาเส้นทาง **"เมื่อต้องการส่งข้อมูล (On-Demand)"**:
1. **Route Request (RREQ):** เมื่อโหนดต้องการส่งข้อมูลไปยังปลายทางที่ไม่มีในตารางเส้นทาง จะทำการบรอดแคสต์แพ็กเกต RREQ ออกไป
2. **Route Reply (RREP):** โหนดระหว่างทางจะส่งต่อ RREQ ไปเรื่อยๆ จนถึงโหนดปลายทาง (หรือโหนดที่มีเส้นทางสดใหม่อยู่แล้ว) โหนดนั้นจะส่งแพ็กเกต RREP ย้อนกลับมาตามเส้นทางที่ดีที่สุด
3. **Route Cost / Link Quality (LQI):** เส้นทางจะถูกเลือกโดยพิจารณาจากคุณภาพสัญญาณ (LQI) และจำนวนทอด (Hop Count) ที่มีค่าน้อยที่สุด

### 2.2 กลไกการซ่อมแซมตัวเองอัตโนมัติ (Self-Healing)
* ในฟาร์ม หากมีโหนด Router ตัวใดตัวหนึ่งดับ (เช่น ปลั๊กไฟหลุด หรือถูกตัดไฟ)
* โหนดข้างเคียงจะตรวจพบว่าไม่ได้รับการตอบรับ (ACK Timeout)
* ระบบ NWK Layer จะเริ่มค้นหาเส้นทางสำรองผ่าน Router ตัวอื่นในทันที โดยที่ข้อมูลของเซนเซอร์ปลายทางไม่สูญหาย และผู้ใช้งานไม่ต้องเข้าไปตั้งค่าใหม่ใดๆ ทั้งสิ้น

## 3. กลไกการประหยัดพลังงานของโหนดเซนเซอร์ (ZED Polling & Sleep)

สำหรับเซนเซอร์ที่ใช้แบตเตอรี่ (ZED):
* ZED จะหลับ (Sleep) เกือบ 99% ของเวลาทั้งหมด ปิดทั้ง CPU และโมดูลวิทยุ 2.4 GHz
* เมื่อครบคาบเวลา (เช่น ทุกๆ 5 นาที จาก Internal RTC Timer):
  1. ZED ตื่นขึ้นมา (Wake up) ในเวลาไม่กี่มิลลิวินาที
  2. อ่านค่าจากเซนเซอร์ดิน/อากาศ
  3. เปิดภาครับส่งวิทยุ และส่งแพ็กเกตขึ้นไปยัง Parent Router
  4. ทำการถาม Parent ว่ามีคำสั่งควบคุมลงมาหาตัวเองหรือไม่ (**Data Request / Poll**)
  5. เมื่อส่งและรับ ACK สำเร็จ จะกลับเข้าสู่โหมด Deep Sleep ทันที (รอบการทำงานรวมไม่เกิน 50–100 ms)
