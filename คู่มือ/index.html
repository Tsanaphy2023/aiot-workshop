5 การปิดเครื่องเสมือนอย่างปลอดภัย (Safe Shutdown)

เมื่อทดสอบเสร็จเรียบร้อยแล้ว ให้ปิดเครื่องตามขั้นตอนดังนี้เพื่อไม่ให้ข้อมูลเสียหาย:

✅ วิธีปิดที่ถูกต้อง:
1. กดปุ่มกากบาทปิดหน้าต่างจอดำของเครื่องเสมือน
2. เลือก "Send the shutdown signal"
3. กดปุ่ม OK ระบบจะจัดเก็บข้อมูลและปิดตัวเองลงเรียบร้อย
❌ ข้อห้าม:
• ห้ามเลือก "Power off" เด็ดขาด เพราะเทียบเท่ากับการดึงปลั๊กไฟ อาจทำให้ไฟล์พังจนต้องโหลดใหม่
• ไม่ต้องเลือก "Save the machine state"
6 เช็กลิสต์ของที่ต้องนำมาในวันอบรม
  • ✓ แล็ปท็อปที่ติดตั้ง VirtualBox และนำเข้าเครื่อง Farm Workshop สำเร็จแล้ว
  • ✓ สายชาร์จ / อะแดปเตอร์จ่ายไฟของแล็ปท็อป (แนะนำพกปลั๊กพ่วงมาด้วย)
  • ✓ สมาร์ตโฟน (เปิด Wi-Fi ได้) สำหรับใช้ทดลองเปิดแดชบอร์ดควบคุม
  • ✓ เมาส์แยก (แนะนำ เพื่อความสะดวกในการลากวางบล็อกคำสั่ง)
7 การแก้ไขปัญหาเบื้องต้น (FAQ / Troubleshooting)
❓ หน้าจอดำขึ้นเลข IP เป็น 169.254.x.x หรือไม่มีเลข IP
เกิดจากแล็ปท็อปไม่ได้ต่อ Wi-Fi ก่อนเปิดเครื่องเสมือน หรือการ์ดเน็ตเวิร์กตั้งค่าผิด
วิธีแก้: ปิดเครื่องด้วย Shutdown signal → ต่อ Wi-Fi ของเครื่องหลักให้เรียบร้อย → ไปที่ VirtualBox Settings → Network → ตรวจสอบว่าเลือก Bridged Adapter และเลือกการ์ด Wi-Fi (เช่น en0: Wi-Fi บน Mac) → กด Start ใหม่อีกครั้ง
❓ พิมพ์เลข IP แล้วหน้าเว็บไม่โหลดหรือโหลดค้าง
วิธีแก้:
1. ตรวจสอบว่าพิมพ์ขึ้นต้นด้วย http:// ไม่ใช่ https://
2. ให้ลองเติมพอร์ต :8123 ต่อท้าย เช่น http://192.168.1.50:8123
3. หากแล็ปท็อปเปิด VPN ให้กดปิด (Disconnect) VPN ก่อนใช้งาน
❓ ติดตั้งแล้วเผลอกด Power off เครื่องมีโอกาสพังไหม?
หากกดไปเพียงครั้งเดียวและระบบยังไม่เริ่มเขียนฐานข้อมูล ระบบอาจยังบูตขึ้นได้ แต่หากเปิดแล้วขึ้น Error จอดำค้าง วิธีแก้ที่ดีที่สุดคือ ลบเครื่องเสมือนตัวเดิมออก (Remove only) แล้วทำขั้นตอน Import Appliance... ไฟล์ .ova ใหม่อีกครั้ง

คู่มือมาตรฐานสำหรับวิทยากร & ผู้เรียน

คู่มือมาตรฐานฉบับสมบูรณ์สำหรับวิทยากร ผู้ช่วยสอน (TA) และผู้เข้าอบรม ในการจัดกิจกรรมเชิงปฏิบัติการ Smart Farm AIoT ทั้ง 4 ช่วง (11 กิจกรรม) แต่ละคู่มือประกอบด้วย บทนำวิศวกรรม, แผนคุมเวลา (Facilitator Matrix), ผังวงจรฮาร์ดแวร์, โค้ด YAML/Config สำเร็จรูป, เฉลยใบงานครบถ้วน, การแก้ไขปัญหาหน้างาน (FAQ) และเกณฑ์การประเมิน 20 คะแนน

แบบทดสอบวัดผลการปฏิบัติการจริง ครอบคลุมการต่อวงจรเซนเซอร์, วงจรรีเลย์, ตรรกะ Automation ใน Home Assistant, การควบคุมแบบ Hysteresis, เครือข่ายฟาร์ม, สถาปัตยกรรม Cloud, โพรโทคอล ESP-NOW และระบบรดน้ำอัตโนมัติ

🏠 ชุดที่ 1: ระบบควบคุมภายในฟาร์ม Home Assistant & Automation (10 ข้อ)

ข้อ 1: กดเปิด–ปิดรีเลย์แล้วไฟติด แต่พอบังแสงจนต่ำกว่าเกณฑ์ ไฟกลับไม่เปิดตามกฎอัตโนมัติ ควรตรวจอะไรต่อ?
  • ก. ตรวจแรงดันของแหล่งจ่ายไฟที่ต่อให้หลอด
  • ข. ตรวจขั้วหน้าสัมผัสรีเลย์ที่ต่อกับหลอดไฟ
  • ค. ตรวจการตอบสนองของเซนเซอร์บนบอร์ด
  • ง. ตรวจการเปิดใช้กฎและอุปกรณ์ที่เลือกในกฎ
✅ เฉลยข้อ ง: เพราะกด Manual ติดแสดงว่าฮาร์ดแวร์รีเลย์และไฟปกติ และค่าแสงใน Home Assistant ลดลงแสดงว่าเซนเซอร์และเน็ตปกติ ปัญหาจึงอยู่ที่ตรรกะหรือการเปิดใช้งาน Automation ใน Home Assistant
ข้อ 2: บังแสงแล้วค่าบนเว็บของบอร์ดลดลง แต่ Home Assistant ยังแสดงค่าเดิม ควรตรวจอะไรเป็นอันดับแรก?
  • ก. การต่อหลอดไฟกับหน้าสัมผัสของรีเลย์
  • ข. แรงดันไฟจากแหล่งจ่ายที่ต่อให้หลอด LED
  • ค. ตำแหน่งติดตั้งหลอดไฟเมื่อเทียบกับเซนเซอร์
  • ง. การส่งค่าจากบอร์ดเข้า Home Assistant
✅ เฉลยข้อ ง: ค่าบนเว็บของบอร์ดลดลงแปลว่าฮาร์ดแวร์เซนเซอร์ปกติ แต่ไม่เข้า Home Assistant แสดงว่าเกิดปัญหาที่การเชื่อมต่อเครือข่าย Wi-Fi หรือ ESPHome API หลุด
ข้อ 3: ต้องการเปิดไฟเมื่อมืดและเวลาตั้งแต่ 18.30 น. หากตั้ง Trigger แสงอย่างเดียวแล้วมืดก่อนเวลา ไฟจะไม่เปิดตอน 18.30 น. ต้องแก้ไขอย่างไร?
  • ก. ใช้ Trigger แสงและเวลา แล้วตรวจทั้งเวลาและแสงใน Condition
  • ข. ใช้ Trigger แสงอย่างเดียว แล้วตรวจเวลาใน Condition สองครั้ง
  • ค. ใช้ Trigger แสงและเวลา แล้วตรวจเฉพาะเวลาใน Condition
  • ง. ใช้ Trigger เวลาอย่างเดียว แล้วตรวจว่าแสงต่ำกว่าเกณฑ์หรือไม่
✅ เฉลยข้อ ก: Trigger ใน Home Assistant เป็นแบบ Edge-trigger ทำงานเฉพาะตอนข้ามเส้นเกณฑ์ จึงต้องดักทั้งสองเหตุการณ์ (แสงมืด หรือ ถึงเวลา) และมี Condition ตรวจสอบความถูกต้องทั้งสองเงื่อนไขเสมอ
ข้อ 4: ระบบ A ใช้เครื่องในฟาร์มผ่าน WiFi ส่วนระบบ B พึ่งพาคลาวด์ ถ้าเน็ตหลุดแต่ไฟและ WiFi ยังปกติ ทั้งสองระบบจะเป็นอย่างไร?
  • ก. ระบบ A ใช้กฎได้ ระบบ B รับคำสั่งใหม่ไม่ได้
  • ข. ทั้งสองระบบยังใช้กฎได้ เพราะ WiFi ไม่ขัดข้อง
  • ค. ระบบ A ใช้กฎไม่ได้ ระบบ B ยังรับคำสั่งได้
  • ง. ทั้งสองระบบใช้กฎไม่ได้ เพราะอินเทอร์เน็ตขาด
✅ เฉลยข้อ ก: ระบบ A เป็น Local Edge (เช่น Home Assistant ในฟาร์ม) ประมวลผลในวงแลนได้ตามปกติ ส่วนระบบ B ขาดเน็ตทำให้ติดต่อคลาวด์ไม่ได้จึงรับคำสั่งไม่ได้
ข้อ 5: สั่งเปิดรีเลย์แล้วไฟ LED บนบอร์ดรีเลย์ติด แต่หลอดไฟภายนอกไม่สว่าง ควรด่วนสรุปอย่างไร?
  • ก. ปัญหาอยู่ที่การรับคำสั่งของรีเลย์
  • ข. หน้าสัมผัสต่อถูกแล้ว จึงเหลือเพียงปัญหาแรงดัน
  • ค. ปัญหาอยู่ที่ตัวหลอด เพราะรีเลย์เปิดแล้ว
  • ง. ยังระบุไม่ได้ ต้องตรวจวงจรหลอดไฟต่อ
✅ เฉลยข้อ ง: ไฟบนบอร์ดรีเลย์ติดยืนยันเฉพาะวงจรควบคุม (Control) ทำงาน แต่วงจรโหลด (Load) อาจต่อขั้ว NO/NC ผิด สายหลวม ขั้วสลับ หรือหลอดขาด จึงต้องตรวจไล่วงจรต่อไป
ข้อ 6: ตั้งกฎเปิดไฟเมื่อแสง < 40 และปิดเมื่อ > 60 (เริ่มต้นแสง 70 ไฟดับ) จากนั้นค่าเปลี่ยนเป็น 30, 50, 70, 50 สถานะไฟจะเป็นอย่างไร?
  • ก. ครั้งแรกดับ ครั้งที่สองติด ครั้งที่สามดับ และครั้งสุดท้ายติด
  • ข. ครั้งแรกติด ครั้งที่สองดับ ครั้งที่สามดับ และครั้งสุดท้ายดับ
  • ค. ครั้งแรกติด ครั้งที่สองติด ครั้งที่สามดับ และครั้งสุดท้ายติด
  • ง. ครั้งแรกติด ครั้งที่สองติด ครั้งที่สามดับ และครั้งสุดท้ายดับ
✅ เฉลยข้อ ง: เข้าหลักการ Deadband (40–60): 30 (<40) ติด $\rightarrow$ 50 (คงเดิม) ติด $\rightarrow$ 70 (>60) ดับ $\rightarrow$ 50 (คงเดิม) ดับ
ข้อ 7: ควบคุมผ่านคลาวด์ได้ แล้วเครื่อง Home Assistant ที่ฟาร์มเกิดดับไป แต่โทรศัพท์ยังมีเน็ต จะเกิดอะไรขึ้น?
  • ก. คลาวด์ประมวลผลกฎและสั่งอุปกรณ์แทน
  • ข. ควบคุมผ่านคลาวด์ไม่ได้จนกว่าเครื่องที่ฟาร์มจะทำงาน
  • ค. รีเลย์เชื่อมกับโทรศัพท์โดยตรงเพื่อรับคำสั่ง
  • ง. โทรศัพท์ประมวลผลกฎผ่านหน้าเว็บที่เปิดไว้
✅ เฉลยข้อ ข: คลาวด์เป็นเพียงท่อเชื่อมต่อไปยังเครื่องที่ฟาร์ม เมื่อปลายทางดับ ระบบทั้งหมดจะขาดการติดต่อจนกว่าเครื่องที่ฟาร์มจะบูตกลับขึ้นมา
ข้อ 8: โรงเรือนมีไฟฟ้าและสัญญาณ WiFi ครอบคลุมอยู่แล้ว ส่งข้อมูลทุกนาทีและไม่ใช้แบตเตอรี่ ควรเลือกการเชื่อมต่อแบบใด?
  • ก. เปลี่ยนบอร์ดทุกจุดไปใช้เครือข่าย LoRa
  • ข. เดินสาย RS-485 เชื่อมจุดวัดเข้าระบบ
  • ค. ติดตั้งโมเด็มมือถือให้บอร์ดแต่ละจุดใช้สัญญาณ 4G, 5G จากมือถือ
  • ง. ใช้ WiFi เดิมเหมาะสมอยู่แล้ว
✅ เฉลยข้อ ง: ใช้โครงสร้างพื้นฐานเดิมที่มีความพร้อม ประหยัดต้นทุนอุปกรณ์และค่าบริการรายเดือนได้สูงสุด
ข้อ 9: ต้องติดตั้งจุดวัดความชื้นในแปลงส่งข้อมูลทุก 10 นาที ระยะ LoRa ส่งถึงบ้านได้ ต้องเตรียมการเชื่อมต่ออย่างไร?
  • ก. ส่งค่าจากเซนเซอร์ผ่าน LoRa เข้าเราเตอร์ WiFi โดยตรง
  • ข. ส่งค่าผ่านตัวส่งและตัวรับ LoRa อุปกรณ์จะถูกเพิ่มเข้า Home Assistant เอง พร้อมใช้งานได้เองทันที
  • ค. ส่งค่าจากเซนเซอร์ผ่าน LoRa เข้า Home Assistant โดยไม่ใช้ตัวรับ
  • ง. ส่งค่าผ่านตัวส่งและตัวรับ LoRa แล้วเพิ่มอุปกรณ์พร้อมตั้งค่าใน Home Assistant เพื่อให้พร้อมใช้งาน
✅ เฉลยข้อ ง: ต้องมีบอร์ดตัวส่ง (Transmitter) ที่แปลง และตัวรับ (Receiver) ที่บ้าน และผู้ใช้ต้องทำการตั้งค่าเพิ่มอุปกรณ์ใน Home Assistant เพื่อให้อ่านค่าได้
ข้อ 10: ตั้ง Automation เปิดไฟด้วย Trigger เวลา 18.30 น. อย่างเดียว จะเกิดปัญหาอะไรถ้าถึงเวลาแล้วแสงยังสูงกว่า 40 และต้องแก้อย่างไร?
  • ก. ไฟไม่เปิด เพราะต้องเกิดทั้งสอง Trigger จึงใช้กฎเดิมได้
  • ข. ไฟเปิดทั้งที่สว่าง จึงต้องเพิ่ม Condition ตรวจว่าแสงต่ำกว่า 40
  • ค. ไฟเปิดตามประวัติแสงที่บันทึกไว้ จึงควรลบข้อมูลย้อนหลัง
  • ง. ไฟไม่เปิด เพราะ Trigger แสงตรวจความมืดแล้ว จึงใช้กฎเดิมได้
✅ เฉลยข้อ ข: ถ้าตั้ง Trigger เวลาอย่างเดียว ถึงเวลาระบบจะสั่งเปิดไฟทันทีแม้แสงยังสว่างอยู่ จึงต้องใส่ Condition เพื่อเช็คระดับแสงก่อนสั่งเปิดไฟ

☁️ ชุดที่ 2: ระบบ Cloud, ESP-NOW & รดน้ำอัตโนมัติ (Module 4)

10 ข้อปฏิบัติการ

แบบทดสอบวัดผลการปฏิบัติการเชื่อมต่อเซิร์ฟเวอร์ Cloud (AWS EC2, Flask API), การสื่อสารระยะไกลด้วยโพรโทคอล ESP-NOW, สถาปัตยกรรม HTTP Polling, การตั้งเวลาด้วย Cron และสคริปต์ตัดสินใจรดน้ำอัตโนมัติ

ข้อ 11: หากมีการยิง POST ไปที่ /api/data โดยข้อมูลที่ส่งไม่มีคีย์ temp หรือ hum เซิร์ฟเวอร์จะตอบกลับอย่างไร?
  • ก. ตอบสถานะ 200 พร้อมบันทึกค่าว่างลง CSV
  • ข. ตอบสถานะ 400 พร้อมข้อความแจ้งว่า payload ไม่ถูกต้อง
  • ค. เปลี่ยนไปเรียกคำสั่งรดน้ำแทน
  • ง. ตอบสถานะ 500 แล้วหยุดการทำงานของเซิร์ฟเวอร์
✅ เฉลยข้อ ข: ในโค้ด server_app.py ตรวจสอบโครงสร้างข้อมูลด้วย if not data or 'temp' not in data or 'hum' not in data: หากข้อมูลไม่ครบจะตอบกลับสถานะ 400 (Bad Request) พร้อมข้อความแจ้งข้อผิดพลาดทันที โดยไม่บันทึกลง CSV
ข้อ 12: Cron รันสคริปต์ trigger_water.py แล้วพบว่าค่าความชื้นล่าสุดในไฟล์ CSV คือ 85% ระบบจะทำอย่างไร (เกณฑ์ตั้งไว้ที่ 80%)?
  • ก. สั่งเปิดน้ำเป็นเวลาครึ่งหนึ่งของที่กำหนดไว้
  • ข. สั่งเปิดน้ำทันทีเพราะค่าความชื้นสูง
  • ค. ข้ามการรดน้ำ เพราะถือว่าฝนตกหรือดินชื้นเพียงพอแล้ว
  • ง. แจ้งข้อผิดพลาดว่าไม่มีข้อมูลความชื้น
✅ เฉลยข้อ ค: ใน trigger_water.py มีเงื่อนไข if hum >= HUMIDITY_THRESHOLD: (80%) ค่า 85% สูงกว่าเกณฑ์ ระบบจะข้ามรอบการรดน้ำ (Skip) เพื่อประหยัดน้ำและป้องกันรากพืชเน่า
ข้อ 13: บรรทัดใน crontab ที่เขียนว่า 0 7,17 * * * หมายความว่าอย่างไร?
  • ก. ทำงานทุกวันที่ 7 และ 17 ของเดือน
  • ข. ทำงานทุก 7 ถึง 17 นาที
  • ค. ทำงานทุกวัน เวลา 07:00 น. และ 17:00 น.
  • ง. ทำงานทุก 17 ชั่วโมง เริ่มตอน 7 โมง
✅ เฉลยข้อ ค: รูปแบบ 5 ช่องของ Crontab คือ [นาที] [ชั่วโมง] [วัน] [เดือน] [วันในสัปดาห์] ค่า 0 7,17 * * * จึงหมายถึง นาทีที่ 0 ของเวลา 07:00 น. และ 17:00 น. ทุกวัน
ข้อ 14: โค้ดบอร์ด 1 กำหนด SEND_INTERVAL = 300 หมายความว่าอย่างไร?
  • ก. ส่งค่าเซนเซอร์ทุก 5 นาที
  • ข. ส่งค่าเซนเซอร์ได้สูงสุด 300 ครั้งต่อวัน
  • ค. ส่งค่าเซนเซอร์ทุก 300 มิลลิวินาที
  • ง. เก็บข้อมูลย้อนหลังได้ 300 แถว
✅ เฉลยข้อ ก: หน่วยเวลาในคำสั่งหน่วงเวลาของ Python คือวินาที ดังนั้น 300 วินาที ÷ 60 = 5 นาที เป็นการส่งข้อมูลทุกๆ 5 นาทีเพื่อช่วยประหยัดแบตเตอรี่ในแปลงเกษตร
ข้อ 15: บอร์ด 2 ตั้งค่า POLL_INTERVAL = 15 เมื่อผู้ใช้กดสั่งรดน้ำผ่านคลาวด์ คำสั่งอาจใช้เวลานานที่สุดประมาณเท่าใดกว่าวาล์วน้ำจะเปิด?
  • ก. ประมาณ 15 วินาที ตามรอบที่บอร์ดไปถามคำสั่ง
  • ข. ประมาณ 5 นาที ตามรอบการส่งค่าเซนเซอร์
  • ค. ทันทีเสมอ เพราะเซิร์ฟเวอร์ส่งคำสั่งไปหาบอร์ดโดยตรง
  • ง. ประมาณ 60 วินาที ตามระยะเวลารดน้ำ
✅ เฉลยข้อ ก: บอร์ด 2 ใช้สถาปัตยกรรมแบบ Polling ยิง HTTP GET ไปถามคำสั่งจากคลาวด์ทุกๆ 15 วินาที หากผู้ใช้กดสั่งหลังจากรอบก่อนหน้าเสร็จพอดี จะต้องรอจนจบรอบถัดไปไม่เกิน 15 วินาที
ข้อ 16: เมื่อบอร์ด 2 เรียก GET /api/command และได้รับคำสั่ง WATER_ON แล้ว เซิร์ฟเวอร์จะทำอย่างไรต่อ?
  • ก. เก็บคำสั่ง WATER_ON ไว้เหมือนเดิมจนกว่าจะมีคำสั่งใหม่มาทับ
  • ข. เคลียร์ค่าคำสั่งกลับเป็น NONE เพื่อไม่ให้บอร์ดสั่งงานซ้ำในรอบถัดไป
  • ค. บันทึกคำสั่งลงไฟล์ sensor_data.csv
  • ง. ส่งคำสั่งเดิมซ้ำอีกครั้งเพื่อความแน่นอน
✅ เฉลยข้อ ข: เซิร์ฟเวอร์มีคำสั่ง pending_command = "NONE" ทันทีหลังส่งคำสั่งออกไป เพื่อป้องกันไม่ให้บอร์ด 2 ที่ส่งคำขอรอบถัดไปได้รับคำสั่งเปิดน้ำซ้ำซ้อน
ข้อ 17: ติดตั้งและรันสคริปต์ Flask บน EC2 เรียบร้อยแล้ว แต่บอร์ด 2 ส่งข้อมูลเข้าไปไม่ได้เลย สิ่งใดควรตรวจสอบเป็นลำดับแรก?

  • ข. ค่า HUMIDITY_THRESHOLD ในสคริปต์รดน้ำ
  • ค. Inbound Rule ของ EC2 ว่าเปิดรับ Traffic พอร์ต 5000 แบบ Custom TCP แล้วหรือยัง
  • ง. จำนวนแถวข้อมูลในไฟล์ sensor_data.csv
✅ เฉลยข้อ ค: ค่าเริ่มต้นของ AWS Security Group จะบล็อกพอร์ตทั้งหมดจากภายนอกยกเว้น SSH (พอร์ต 22) หากไม่เปิด Inbound Rules พอร์ต 5000 แหล่งที่มา Anywhere (0.0.0.0/0) บอร์ดภายนอกจะไม่สามารถส่งข้อมูลเข้ามาได้
ข้อ 18: รันคำสั่ง python3 app.py แล้วโปรแกรมหยุดทำงานทุกครั้งที่ปิดหน้าต่าง Terminal ควรแก้ไขอย่างไรตามที่แนะนำไว้?

  • ข. ย้ายไปรันบน Raspberry Pi แทน
  • ค. รันด้วยคำสั่ง nohup python3 app.py & เพื่อให้ทำงานเป็น Background
  • ง. เปลี่ยนพอร์ตจาก 5000 เป็น 80
✅ เฉลยข้อ ค: คำสั่ง nohup จะสั่งให้ระบบเพิกเฉยต่อสัญญาณ SIGHUP เมื่อปิด Terminal และ & จะผลักโปรแกรมให้ทำงานเป็น Background Process ต่อเนื่องตลอดเวลา
ข้อ 19: หากกรอกค่า BOARD_2_MAC ในโค้ดบอร์ด 1 ไม่ถูกต้อง จะเกิดผลอย่างไร และควรหาค่าที่ถูกได้จากที่ใด?
  • ก. ข้อมูลจะถูกส่งขึ้นคลาวด์โดยตรงแทน
  • ข. ข้อมูลจะส่งไปไม่ถึงปลายทาง ต้องอ่านค่า MAC จากบอร์ด 2 ด้วยคำสั่ง wlan.config('mac')
  • ค. บอร์ด 1 จะรีสตาร์ตซ้ำ ๆ ต้องแก้ด้วยการติดตั้งเฟิร์มแวร์ใหม่
  • ง. ระบบยังทำงานได้ปกติ เพราะ ESP-NOW ค้นหาอุปกรณ์เองอัตโนมัติ
✅ เฉลยข้อ ข: ESP-NOW ส่งข้อมูลแบบ Peer-to-Peer โดยอ้างอิง Hardware MAC Address ของบอร์ดปลายทางโดยตรง หากระบุผิด ข้อมูลจะสูญหาย การอ่านค่า MAC ทำได้โดยใช้คำสั่ง wlan.config('mac') บนบอร์ด 2 ผ่าน MicroPython
ข้อ 20: หากค่าความชื้นล่าสุดคือ 60% ลำดับการทำงานของสคริปต์รดน้ำจะเป็นอย่างไร?
  • ก. ส่งคำสั่งไปยังบอร์ด 1 ผ่าน ESP-NOW โดยตรงโดยไม่ผ่าน API
  • ข. สั่ง WATER_ON แล้วปล่อยให้วาล์วเปิดค้างไว้จนกว่าความชื้นจะถึงเกณฑ์
  • ค. สั่ง WATER_OFF ก่อนแล้วจึงสั่ง WATER_ON
  • ง. สั่ง WATER_ON รอครบ 60 วินาที แล้วจึงสั่ง WATER_OFF
✅ เฉลยข้อ ง: เมื่อความชื้น 60% ต่ำกว่าเกณฑ์ 80% สคริปต์จะยิง POST สั่ง WATER_ON จากนั้นหน่วงเวลาด้วย time.sleep(60) เป็นเวลา 60 วินาที แล้วจึงยิง POST สั่ง WATER_OFF เพื่อปิดวาล์วน้ำ เป็นการควบคุมแบบจำกัดเวลาเพื่อความปลอดภัย
