📌 1. บทนำและแนวคิดวิศวกรรมความปลอดภัย (Fail-safe Engineering)

ในระบบเกษตรอัจฉริยะ ความเสียหายส่วนใหญ่มักไม่ได้เกิดจากตัวระบบทำงานปกติ แต่เกิดจาก "สภาวะผิดปกติทางกายภาพ (Physical Failures)" เช่น น้ำแห้ง, ปั๊มน้ำติดขัด, สัญญาณ Wi-Fi หลุด, หรือเซนเซอร์ชำรุด หากระบบอัตโนมัติทำงานโดยเชื่อถือข้อมูลเพียงด้านเดียว (Blind Trust) จะนำไปสู่ความสูญเสียใหญ่หลวง:

🔥 ปั๊มน้ำไหม้ (Dry-run Burnout)

เมื่อน้ำในบ่อ/ถังแห้ง ปั๊มน้ำไดอะแฟรมที่เดินแห้งจะเกิดความร้อนสะสม ยางไดอะแฟรมฉีกขาด และขดลวดมอเตอร์ไหม้ในเวลาอันสั้น

🌊 แปลงพืชท่วมขัง (Flooding/Root Rot)

หากบอร์ดเซนเซอร์ดับ ระบบไม่ได้รับค่าความชื้น ปั๊มที่เปิดอยู่จะไม่ยอมตัด น้ำท่วมขังแปลงพืช รากเน่าเสียหาย และสูบน้ำทิ้งจนหมด

⚠️ รดน้ำไม่ทำงานโดยไม่มีใครรู้

สถานะรีเลย์บนหน้าจอขึ้น On แต่สายปั๊มหลุดหรือใบพัดติดขัด พืชไม่ได้รับน้ำเฉาตาย โดยที่เจ้าของฟาร์มเข้าใจว่าระบบรดน้ำปกติ

💡
หัวใจของกิจกรรมที่ 5: มุ่งฝึกฝนทักษะ "Fault Injection → Observe → Mitigate → Verify" (จำลองปัญหาจริง → สังเกตพฤติกรรม → เขียนกฎความปลอดภัย → ตรวจสอบซ้ำด้วย Traces)

รายการอุปกรณ์ประจำกลุ่ม (Hardware BOM)

  • บอร์ด 1 (GoGo-IoT ESP32): มีเซนเซอร์ SHT30 วัดอากาศ, ตัวตรวจจับแรงสั่นสะเทือน (Vibration), ช่องต่อสวิตช์ลูกลอย (Float Switch)
  • บอร์ด 2 (GoGo-Relay ESP32): โมดูลรีเลย์ตัดต่อไฟ 12V DC พร้อมเทอร์มินัล COM/NO
  • ปั๊มน้ำ 12V DC: จำลองการรดน้ำ (ทดสอบเดินแห้งในห้องเรียน)
  • แก้วน้ำทรงสูง: สำหรับจุ่มสวิตช์ลูกลอยจำลองระดับน้ำในถังพัก

🧪 4. รายละเอียดและโค้ดของกฎความปลอดภัยทั้ง 4 ข้อ

ฐานการทดลองที่ 5.1

1) ปัญหาน้ำแห้งแต่ปั๊มยังเดิน (Low Water / Dry-Run Protection)

ปัญหา: สวิตช์ลูกลอยตกเป็น Dry แต่อนุญาตให้เปิดปั๊มได้ ทำให้ปั๊มเดินแห้งจนร้อนและไหม้

กลไกแก้ไข: ตรวจจับ 2 เหตุการณ์: เมื่อลูกลอยเปลี่ยนเป็น Dry ขณะปั๊มเปิดอยู่ หรือ มีคนสั่งเปิดปั๊มขณะที่น้ำแห้งอยู่แล้ว ให้ตัดรีเลย์ทันที พร้อมแจ้งเตือน

YAML: Automation - Fail-safe น้ำหมด 
alias: Fail-safe - น้ำหมด
description: ตัดปั๊มทันทีถ้าน้ำในถังต่ำ (Dry) และมีคนสั่ง On หรือน้ำแห้งระหว่างทำงาน
trigger:
  - platform: state
    entity_id: binary_sensor.gogo_iot_red_242dcc_switchnam_float_switch
    to: "off" # Moisture cleared (Dry)
  - platform: state
    entity_id: switch.gogo_relay_red_b97df0_riley_relay
    to: "on"
condition:
  - condition: state
    entity_id: binary_sensor.gogo_iot_red_242dcc_switchnam_float_switch
    state: "off" # Moisture is not detected
action:
  - service: switch.turn_off
    target:
      entity_id: switch.gogo_relay_red_b97df0_riley_relay
  - service: persistent_notification.create
    data:
      title: "ระบบความปลอดภัย"
      message: "น้ำในถังต่ำ หยุดปั๊มแล้ว"
mode: single
⚠️
ต้องอัปเดตในกฎเดิมด้วย: เข้าไปที่กฎ รดน้ำ - เปิดปั๊ม เพิ่ม Condition ตรวจสวิตช์ลูกลอยเป็น Wet (on) เพื่อไม่ให้กฎอัตโนมัติสั่งเปิดปั๊มขณะน้ำแห้ง
ฐานการทดลองที่ 5.2

2) ปัญหาสั่งแล้วปั๊มไม่เดิน (Pump Stall / Wire Disconnected)

ปัญหา: รีเลย์ On แต่ปั๊มเงียบสนิท ไม่สั่น (สายหลุด/มอเตอร์ติด) ระบบสั่งงานเปิดทิ้งไว้โดยไม่มีน้ำไหล

กลไกแก้ไข: เมื่อรีเลย์เปิดค้างครบ 15 วินาที แล้วเซนเซอร์ตรวจจับการสั่นยังเป็น Off ให้ตัดรีเลย์และแจ้งเตือน

YAML: Automation - Fail-safe สั่งแล้วไม่เดิน 
alias: Fail-safe - สั่งแล้วไม่เดิน
description: ตัดการทำงานเมื่อสั่งเปิดปั๊มแล้วไม่มีแรงสั่นสะเทือนภายใน 15 วินาที
trigger:
  - platform: state
    entity_id: switch.gogo_relay_red_b97df0_riley_relay
    to: "on"
    for:
      seconds: 15
condition:
  - condition: state
    entity_id: binary_sensor.gogo_iot_red_242dcc_khwamsansatheuxn_vibration
    state: "off"
action:
  - service: switch.turn_off
    target:
      entity_id: switch.gogo_relay_red_b97df0_riley_relay
  - service: persistent_notification.create
    data:
      title: "ระบบความปลอดภัย"
      message: "สั่งปั๊มแล้วแต่ไม่มีการสั่น ตรวจสายและระดับน้ำ"
mode: single
ฐานการทดลองที่ 5.3

3) ปัญหาบอร์ดเซนเซอร์ดับ / หลุดการเชื่อมต่อ (Sensor Offline)

ปัญหา: บอร์ดเซนเซอร์ในสวนแบตหมด สัญญาณหลุด ค่ากลายเป็น unavailable ปั๊มเปิดค้างไม่มีทางตัด

กลไกแก้ไข: เมื่อความชื้นเปลี่ยนเป็น unavailable หรือ unknown ให้สั่งปิดรีเลย์ทันที

YAML: Automation - Fail-safe เซนเซอร์หาย 
alias: Fail-safe - เซนเซอร์หาย
description: สั่งหยุดปั๊มทันทีเมื่อบอร์ดเซนเซอร์ออฟไลน์หรืออ่านค่าไม่ได้
trigger:
  - platform: state
    entity_id: sensor.gogo_iot_red_242dcc_khwamchun_humidity
    to:
      - "unavailable"
      - "unknown"
action:
  - service: switch.turn_off
    target:
      entity_id: switch.gogo_relay_red_b97df0_riley_relay
  - service: persistent_notification.create
    data:
      title: "ระบบความปลอดภัย"
      message: "ไม่ได้รับค่าจากเซนเซอร์ หยุดปั๊มเพื่อความปลอดภัย"
mode: single
ฐานการทดลองที่ 5.4

4) ปัญหาปั๊มเดินนานเกินไป (Pump Overrun / Safety Timeout)

ปัญหา: ท่อส่งน้ำหลุด น้ำไม่ถึงแปลง หรือเซนเซอร์ดินอ่านค่าไม่ขึ้น ปั๊มเดินตลอดเวลาสูบน้ำทิ้งจนหมด

กลไกแก้ไข: กำหนดเพดานเวลาสูงสุด (Safety Timeout) เมื่อปั๊มเปิดค้างครบ 30 วินาที ให้สั่งตัดการทำงาน

YAML: Automation - Fail-safe จำกัดเวลาเปิดปั๊ม 
alias: Fail-safe - จำกัดเวลาเปิดปั๊ม
description: ตัดปั๊มทันทีเมื่อทำงานต่อเนื่องครบ 30 วินาที ป้องกันน้ำท่วมหรือท่อแตก
trigger:
  - platform: state
    entity_id: switch.gogo_relay_red_b97df0_riley_relay
    to: "on"
    for:
      seconds: 30
action:
  - service: switch.turn_off
    target:
      entity_id: switch.gogo_relay_red_b97df0_riley_relay
  - service: persistent_notification.create
    data:
      title: "ระบบความปลอดภัย"
      message: "ปั๊มเดินเกินเวลา ตัดการทำงานแล้ว โปรดตรวจสอบ"
mode: single

📅 5. แผนการบำรุงรักษาเชิงป้องกัน 5 ระบบหลัก (Preventive Maintenance)

การบำรุงรักษาเชิงป้องกันช่วยลดโอกาสเกิด Failure ได้มากกว่า 80% ตารางมาตรฐานสำหรับฟาร์มจริง:

รายการอุปกรณ์ ผู้รับผิดชอบ ความถี่ สิ่งที่ต้องตรวจเช็กและวิธีการปฏิบัติ
1. เซนเซอร์บนบอร์ด (SHT30) เจ้าของฟาร์ม ทุกสัปดาห์ เช็ดฝุ่น/ตะไคร่ ตรวจสายและเทียบค่าอ่านกับปรอทวัดมาตรฐาน
2. สวิตช์ลูกลอย (Float Switch) คนงาน/ผู้ดูแล ทุก 3 วัน ทดสอบขยับแกนลูกลอยขึ้นลง ล้างคราบเมือกและตะกรันติดขัด
3. ปั๊มน้ำและระบบท่อส่ง ช่างประจำฟาร์ม ทุกเดือน ตรวจรอยรั่วข้อต่อ ตะแกรงกรอง และวัดการสั่นสะเทือน/ความร้อนมอเตอร์
4. รีเลย์และตู้ควบคุม ช่างไฟฟ้า ทุก 3 เดือน ตรวจขันขั้วต่อสายไฟ รอยไหม้หน้าสัมผัส และตรวจความชื้นในตู้
5. เครือข่าย & Home Assistant ผู้ดูแลระบบ/เจ้าของ ทุกสัปดาห์ ตรวจสถานะ Wi-Fi, สัญญาณ RSSI และสำรองฐานข้อมูล/กฎอัตโนมัติ

แนวทางคำตอบมาตรฐาน:
ถ้า Home Assistant ดับ กฎใน HA จะหยุดทำงานทั้งหมดและไม่สามารถสั่งหยุดปั๊มได้ จึงต้องเพิ่มการป้องกันระดับฮาร์ดแวร์และเฟิร์มแวร์:
  1. Hardware Interlock: ต่อสวิตช์ลูกลอยตัดวงจรไฟเลี้ยงคอยล์รีเลย์หรือปั๊มโดยตรงทางกายภาพ (Fail-safe physical loop) น้ำแห้งวงจรจะตัดขาดทันที
  2. Firmware Safety Timeout: ตั้ง Watchdog Timer บนบอร์ดรีเลย์ ESP32 หากเปิดปั๊มนานเกินกำหนด หรือขาดสัญญาณ Heartbeat จากเซิร์ฟเวอร์ ให้สั่งตัดรีเลย์เองโดยอิสระ

🎯 7. เกณฑ์การประเมินผลการเรียนรู้ (Assessment Rubric)

หัวข้อประเมิน ดีเยี่ยม (3 คะแนน) ผ่านเกณฑ์ (2 คะแนน) ต้องปรับปรุง (1 คะแนน)
1. การจำลองปัญหา จำลองได้ครบ 4 ข้อ และอธิบายอาการทางกายภาพได้ถูกต้อง จำลองได้ 3 ข้อ สังเกตอาการได้ จำลองไม่ครบหรือไม่เข้าใจปัญหา
2. กฎความปลอดภัย สร้างครบ 4 กฎ มี Trigger, Condition, Action และแจ้งเตือนถูกต้อง สร้างได้ 3 กฎ และสามารถตัดปั๊มได้ กฎไม่ทำงาน หรือระบุ Entity ID ผิด
3. การวิเคราะห์ Traces เปิด Traces ระบุชื่อกฎและเส้นทางขั้นตอนที่ทำงานได้ชัดเจน เปิดดู Traces ได้ แต่อธิบายได้บางส่วน ไม่สามารถเปิดดู Traces ได้
4. แผนบำรุงรักษา & สรุป กรอกตารางครบ 5 ข้อ และอธิบายแนวคิด Hardware Interlock ได้ลึกซึ้ง กรอกตารางครบถ้วน และตอบแนวคิดสรุปได้ กรอกไม่ครบ หรือขาดคำอธิบาย

❓ 8. ปัญหาที่พบบ่อยและวิธีแก้ไข (Troubleshooting FAQ)

Q1: ยกลูกลอยขึ้นเป็น Dry แล้วสั่ง On แต่ทำไมปั๊มยังเดิน?
A: ตรวจสอบว่าในกฎ Fail-safe - น้ำหมด ได้ใส่ Condition เป็น Moisture is not detected (Dry) หรือยัง และในกฎ รดน้ำ - เปิดปั๊ม ได้เพิ่ม Condition ว่าต้องเป็น Wet แล้วหรือยัง

Q2: ในข้อ 5.4 ปั๊มถูกตัดที่ประมาณ 15 วินาที ไม่ยอมรอถึง 30 วินาที?
A: นั่นคือกฎ 5.2 (สั่งแล้วไม่เดิน) ชิงทำงานตัดก่อน เพราะบอร์ด GoGo-IoT ไม่ได้แนบชิดกับปั๊ม ทำให้ไม่ตรวจพบการสั่นสะเทือน ให้เลื่อนบอร์ดไปแตะตัวเรือนปั๊มให้แน่น

Q3: ปิดสวิตช์บอร์ดเซนเซอร์แล้ว ทำไมค่าความชื้นไม่เปลี่ยนเป็น unavailable ทันที?
A: Home Assistant มีช่วงเวลา Keep-alive Timeout ของการเชื่อมต่อ ESPHome ประมาณ 5–15 วินาทีก่อนจะตัดสินว่าอุปกรณ์ออฟไลน์ ให้รอประมาณ 10–15 วินาที
